## Overview

The **Reviews** feature (introduced in v1.1.0) provides a structured workflow for managing AI-suggested code fixes. Instead of immediately applying fixes, you can review, request review, or reject suggestions with documented reasoning.

## How It Works

When Guardian detects issues and Guru suggests fixes:

1. **Detection**: AI identifies an issue
2. **Proposal**: A fix is generated and added to the queue
3. **Review**: You review the proposal in the Reviews panel
4. **Decision**: Apply, reject, or request review

## Accessing Reviews

Click the **Reviews** tab in the left sidebar to open the review queue.

## Review Queue Interface

The Reviews panel shows:

| Section | Description |
|---------|-------------|
| **Pending** | Proposals awaiting your review |
| **Done** | Previously reviewed proposals (applied/rejected) |
| **Details** | Full context and suggested changes |

## Proposal Lifecycle

### Status States

A proposal can be in one of these states:

```
Pending ──► Review Requested ──► Applied
    │
    └──────► Rejected
```

| Status | Description |
|--------|-------------|
| **Pending** | New proposal, not yet reviewed |
| **Review Requested** | Guardian applied the change and awaits your confirmation |
| **Applied** | Fix has been applied to the codebase |
| **Rejected** | Fix was dismissed with reason |

## Taking Action

### Request Review

When you want Guardian to apply the proposed content and queue it for confirmation:

1. Select the proposal
2. Click **Request Review**
3. Guardian applies the change and moves it to "Review Requested"
4. Confirm the outcome in the Guru chat

### Apply Fix

When you're satisfied with the proposal:

1. Review the **Proposed Changes** preview
2. Click **Mark Applied** to confirm
3. The proposal status changes to "Applied"

> **Warning**: Always review the proposed content before applying. Verify it addresses the issue without introducing new problems.

### Reject Fix

When the proposal isn't appropriate:

1. Click **Reject**
2. Optionally add a reason for rejection
3. The proposal moves to "Done" with "Rejected" status

## Understanding Proposals

Each proposal shows:

### Metadata

- **File**: Path to the affected file
- **Severity**: Critical, Warning, or Info
- **Confidence**: AI's confidence score (0.0 - 1.0)
- **Reasoning**: Why this fix is suggested

### Proposed Changes

The proposed content view shows the full updated file content.

> **Note**: Guardian only accepts **full file content**, not patch/diff format. The AI should provide the complete updated file.

## Storage

Fix proposals are stored in your workspace:

```
.guardian-proposals/
└── fix_proposals.jsonl
```

- Append-only log format
- Human-readable JSON Lines
- Survives app restarts
- Can be version controlled (optional)

## Best Practices

### Review Workflow

1. **Start with high severity**: Review Critical proposals first
2. **Check confidence**: High confidence (>0.8) proposals are usually safe
3. **Read reasoning**: Understand *why* the fix is suggested
4. **Test after applying**: Run tests to ensure the fix works
5. **Document rejections**: Note why you rejected for future reference

### When to Reject

Reject proposals when:
- The fix doesn't address the root cause
- It would break existing functionality
- The code style doesn't match your project
- You have a better alternative in mind

### When to Request Review

Request additional context from Guru in the chat if you need more detail before applying a fix.

## Integration with Baseline

Reviewed and applied fixes:
- Are tracked in your baseline
- Won't be flagged as "new" in future scans
- Can be marked as "resolved" in the baseline panel

## Privacy & Security

- Proposals are stored **locally** in your workspace
- No external calls when reviewing (unless you ask Guru in chat)
- You control what gets applied to your codebase
- Rejection reasons are stored locally for your reference

## Troubleshooting

| Issue | Solution |
|-------|----------|
| No proposals showing | Run a scan first to generate proposals |
| Can't apply fix | Check file permissions and ensure file hasn't changed |
| Proposal outdated | Reject and re-scan to get fresh proposals |
| UI not updating | Restart the app (proposals are preserved) |

## CLI Support

For CI/CD integration, use the CLI (if installed in your environment):

```bash
# Generate proposals during scan
guardian-cli scan --root . --out report.json

# Review mode is desktop-only
# Use the desktop app for interactive review
```
