# Private Source + Public Distribution Setup

This guide keeps source code private while preserving:
- in-app auto update
- public download links
- public changelog website

## 1) Make source repository private

Source repository:
- `senoldogann/Guardian` (private)

## 2) Create public distribution repository

Create a new public repository, for example:
- `senoldogann/guardian-distribution`

Rules:
- Do not push source code.
- Only release artifacts and metadata are allowed.

## 3) Configure source repo secrets/variables

In `senoldogann/Guardian` settings:

- Variable: `PUBLIC_DIST_REPO`
  - Value: `senoldogann/guardian-distribution`

- Secret: `PUBLIC_DIST_REPO_TOKEN`
  - PAT scope: write access to distribution repo releases
  - Fine-grained token is recommended

## 4) Updater endpoint

`src-tauri/tauri.conf.json` points to:

`https://github.com/senoldogann/guardian-distribution/releases/latest/download/latest.json`

This file is generated by Tauri release flow and uploaded by the release workflow.

## 5) Release flow

When you create a tag (e.g. `v0.2.5`):

1. Source repo workflow builds signed binaries
2. Source repo release is created
3. Workflow downloads release assets
4. Workflow uploads all assets to public distribution release

Result:
- Desktop app updater can fetch new metadata from public repo
- Website download/changelog pages update automatically

## 6) Website deployment

The Next.js website is in `website/`.

Set Vercel project root to `website/` and deploy.

Optional env vars:
- `GITHUB_RELEASE_OWNER=senoldogann`
- `GITHUB_RELEASE_REPO=guardian-distribution`
- `GITHUB_PUBLIC_READ_TOKEN` (optional; for rate limit headroom)
